# Syndra deep audit — 2026-10-27

Read-only audit of the Go backend, Next/React UI, TrueNAS add-on, contracts,
migrations, and deployment wiring. No code was changed.

This is a findings document, not a remediation plan. It intentionally keeps
file and line references so each item can be verified.

---

## 1. Fix first — critical / high

### 1.1 Compiled claims are deleted after a successful drain, with no rebuild

**Severity:** Critical

- `backend/internal/handlers/access.go:177` rebuilds the user cache before delivery.
- `backend/internal/handlers/access.go:185` calls `svcDeliver`, which drains and calls `invalidateClaims` at `backend/internal/services/propagation/drain.go:516`.
- The only rebuild path is `backend/internal/cache/compiler.go:163`; cache misses fall through to `degradedResponse` at `backend/internal/handlers/action.go:183`, whose default is `fail_closed` with empty claims.
- Bundle/rule/expiry paths invalidate without rebuilding (`backend/internal/services/expiry/sweep.go:81`, `backend/internal/handlers/webhook.go:384,408`).
- Syndra’s own webhook events are dropped by the self-mutation guard (`backend/internal/handlers/webhook_translate.go:76-79`), so the `grant_added` rebuild path does not repair this.

**Impact:** after an applied direct grant, bundle change, rule change, or expiry,
the user can lose all custom claims until something unrelated rebuilds the cache.

**Fix:** rebuild after the drain, or compile on cache miss under a bounded
timeout. Batch by user.

---

### 1.2 The UI proxy cannot PATCH, and drops DELETE bodies

**Severity:** Critical

- `ui/src/app/api/proxy/[...path]/route.ts:82` accepts only `GET | POST | PUT | DELETE`; there is no `PATCH` export.
- `ui/src/lib/queries/useMappings.ts:172-176` sends `PATCH /targets/mappings/{id}`.
- The proxy reads a body only for `POST`/`PUT` (`route.ts:131`), while `useMappings.ts:179-183` sends `{ plan_id }` on `DELETE`.
- The backend requires that body (`backend/internal/handlers/mappings.go:155-167`, `backend/internal/handlers/mapping_plan.go:247-250`).

**Impact:** mapping value edits return 405; mapping deletes for any mapping with
holders fail with `PLAN_REQUIRED`.

---

### 1.3 Failed webhook events can never be retried

**Severity:** Critical

- On failure the event is marked `failed` and a 500 is returned (`backend/internal/handlers/webhook.go:244-252`).
- Zitadel retries with the same idempotency key; `InsertWebhookEvent` uses `ON CONFLICT DO NOTHING` (`backend/internal/db/webhooks.go:30-45`), and the handler returns 200 “already processed” without re-running the switch (`webhook.go:211-218`).
- The same retry hole exists in onboarding: `backend/internal/services/onboarding.go:46-54` treats any duplicate trigger as success regardless of stored status.

**Impact:** a transient DB/cascade failure permanently loses grant, onboarding,
or revocation work.

---

### 1.4 A replayed add-on “blocked” apply is returned as HTTP 200 and recorded as applied

**Severity:** Critical

- `addons/truenas/apply.go:351-365` caches the previous outcome; `:403-411` stores it even when `applyOne` returned a blocked outcome with 409/422 and nil error.
- A replay is written with `http.StatusOK` at `apply.go:358`.
- The backend classifies any 2xx as `OutcomeSucceeded` (`backend/internal/addons/transport.go:314-320`) and the drain records the binding and calls `markApplied` (`backend/internal/services/propagation/addon.go:195-241`) without checking `Effect == "blocked"` or `Conflict`.

**Impact:** a refused or conflicting apply can be recorded as a successful
convergence, binding an account to the wrong subject.

---

### 1.5 The backend is more permissive than the proxy, and its port is published

**Severity:** Critical

- `POST /api/v1/roles` uses `withUserAuth`, not `withOperatorAuth` (`backend/internal/handlers/router.go:175`), and the handler calls Zitadel `AddProjectRole` (`backend/internal/services/roles.go:78-86`).
- `GET /api/v1/applications/{id}/simulate` is `withUserAuth` and takes any `user_id` (`router.go:87`, `backend/internal/handlers/views.go:64-78`).
- `/onboarding/triggers`, `/onboarding/missed`, and `/webhook/events` are `withUserAuth` (`router.go:200-204`).
- `docker-compose.yml:140` publishes `${BACKEND_HOST_PORT:-8080}:8080`.

**Impact:** any member with a valid token can bypass the UI allowlist, create
Zitadel project roles, read another user’s simulated claims, and read operator
logs. The proxy is being treated as the authorization boundary; it is not.

---

### 1.6 `safeReturnPath` is bypassable with control characters — open redirect

**Severity:** Critical

- `ui/src/lib/return-path.ts:21-31` rejects `//` and `/\` but not tabs/newlines.
- `new URL("/\t/evil.com", origin)` resolves to `https://evil.com/`; `/%09/evil.com` decodes to a tab and passes.
- Both the demo login and OIDC callback feed `next` into `buildRedirectUrl` (`ui/src/app/auth/login/route.ts:18-39`, `ui/src/app/auth/callback/route.ts:154`).

**Impact:** a link on the real Syndra domain can land the victim on an attacker
site after sign-in.

**Fix:** reject control characters/whitespace/backslashes anywhere in `next`,
and validate the parsed URL’s origin equals the deployment origin.

---

### 1.7 “Pick a date” grants access for a duration counted from now, not until the chosen date

**Severity:** High

- `ui/src/components/people/GrantDirectAccess.tsx:303-317` converts a custom date to `Math.max(1, daysUntil(custom))`.
- The backend only accepts `duration_days` and computes `now + days` (`backend/internal/handlers/access.go:114-118`).

**Impact:** access can end later than selected; a past date silently grants one
day. West of UTC, `new Date("YYYY-MM-DD")` also displays the previous local day.

**Fix:** send an explicit end date/`until` and validate it, or store the chosen
calendar date.

---

### 1.8 A failed grants read is rendered as permanent access

**Severity:** High

- `PersonAccess` builds `grantsByRole` from `grants.data ?? []`; on error `expires` is null and the row says “No end date” (`ui/src/components/people/PersonAccess.tsx:198,961-971`). `grantsResolved` is only used for the removal dialog.
- `MemberAccess` has no `grants.error` handling; `expiryFor()` returns null and the row says “Given to you” (`ui/src/components/member/MemberAccess.tsx:74,366-370`).

**Impact:** a timeout turns time-limited access into what looks like permanent
access on both operator and member screens.

---

### 1.9 A truncated target read still produces absence findings and queued convergence

**Severity:** High

- `backend/internal/services/drift/addon.go:168-225` sets `res.Truncated` but still calls `partitionByPresence`, persists `merge.Absent` findings, and runs `convergeUnbound`.
- The cap is 5,000 (`addons/truenas/subjects.go:28,140-143`).

**Impact:** an account beyond the cap can be reported “deleted upstream” and an
existing person can be queued for creation. The code comment says a truncated
read cannot support absence, but this path draws it anyway.

---

### 1.10 The add-on shutdown drain is shorter than its own NAS call timeout

**Severity:** High

- `shutdownTimeout = 20s` (`addons/truenas/main.go:45`, used at `:312`), while `callTimeoutSeconds = 30s` (`addons/truenas/nas.go:25`).
- Compose allows 30s (`docker-compose.yml:384`), which is longer than 20s but still shorter than a 30s call.

**Impact:** an in-flight `user.create`/`user.update`/`user.delete` can be cut
mid-call; the drain guarantee is not real.

---

### 1.11 Any empty/non-JSON 2xx is converted into “Backend unreachable”

**Severity:** High

- `ui/src/app/api/proxy/[...path]/route.ts:180` always calls `res.json()`.
- `DELETE /service-accounts/{id}` returns 204 (`backend/internal/handlers/service_accounts.go:78-85`).

**Impact:** unmarking a service account succeeds upstream but the UI reports a
502.

---

### 1.12 Webhook-driven mapping rules still write Zitadel directly, untraced

**Severity:** High (known/dormant)

- `backend/internal/zitadel/orchestrator.go:99-123` and `:130-222` call `AddUserGrant`/`RemoveUserGrant`/`UpdateUserGrant`; failures are logged and the function returns success.
- This is already recorded in `openspec/NEXT.md` as dormant because production has zero mapping rules.

**Impact:** the first mapping rule created will produce mutations with no
ledger/outbox/audit trace, and failed writes are silently lost.

## 2. Backend logic and data integrity

- **Queued revoke still counts as held.** `backend/internal/db/access_requests.go:84-111` subtracts a queued revoke only from `observed`; `granted` still drives `HoldingUntil`/`HoldingForGood`. A person cannot re-request a role whose removal is already queued.
- **“First seen” resets on every complete observation.** `RecordOrgObservation` deletes the whole `zitadel_grants_index` and re-inserts with `created_at DEFAULT NOW()` (`backend/internal/db/observations.go:63-69,117-131`). `UsersFirstSeen` reads that column (`backend/internal/db/insights_lens.go:44-50`), so every sweep makes every grant look new.
- **Mapping blast radius follows one rule hop; the resolver follows chains.** `MappingHolders` joins rules once (`backend/internal/db/mappings.go:240-268`), while `collectUserRoles` runs a fixpoint (`backend/internal/services/views.go:1476-1497`). Mapping edits/deletes can undercount the cohort.
- **Mapping edit/delete is a lost update.** `UpdateRoleMappingValue` and `DeleteRoleMapping` update by id unconditionally (`backend/internal/db/mappings.go:105-120,127-139`); the handler reads the mapping before the plan check (`backend/internal/handlers/mappings.go:125-135`). Two operators can overwrite each other.
- **`EntitlementSet.Given` is stale after per-person overrides.** Role sources are appended at `backend/internal/services/entitlement.go:184-218`; overrides replace `set.Fields` later without updating `Given`. `my_storage` attributes places from `Given` (`backend/internal/handlers/my_storage.go:314`), so it can name a role for a value the override removed.
- **Target revocation can commit the allowance and fail to queue convergence.** `backend/internal/handlers/revocation.go:94-127` writes the allowance, then resolves entitlements; a resolve failure returns 500 with the suspension already committed and no convergence. A retry hits `ALREADY_IN_FORCE`.
- **Missing `rows.Err()` returns partial lists as success.** Examples: `backend/internal/db/access_requests.go:177-185`, `backend/internal/db/grants.go:55-63,116-124,284-292`, `backend/internal/db/webhooks.go:135-144`, `backend/internal/db/onboarding.go:102-111`. A mid-stream error silently truncates access/expiry/request lists.
- **Usage report conflates “source has never delivered” with “no sign-ins in this window.”** `backend/internal/services/insights_usage.go:92-113` returns an empty `HeldNotUsed` if no sign-in landed in the window, so a deployment whose sign-ins stopped 91 days ago reports “nothing held but unused” instead of listing every holder as unused.
- **The plan gate’s cohort can widen after review.** `backend/internal/handlers/mappings.go:173-179` reads holders before the lock; `applyMappingChange` re-reads and converges them inside the lock (`mapping_plan.go:244-257`). A person who gained the role between review and apply is changed without appearing on the approved plan. The code argues this is intentional, but the approval no longer describes the cohort it is applied to.

## 3. Backend performance / scale

- **Governance summary is O(bundles × users).** `backend/internal/services/views.go:1120-1127` calls `bundleImpactFromSnapshot` per bundle; `:1057-1075` loops all users and calls `svcGetBundlesForUser` per user. This is the most expensive page load in the system.
- **Bundle list is N+1.** `backend/internal/handlers/bundles.go:147-159` calls `svcBundleDraft`, `dbBundleIncludesAnything`, and `dbRetireBlockers` per bundle; `BundleDraft` itself performs ~6 reads (`backend/internal/services/bundle_publish.go:71-119`).
- **Access requests are unbounded and `withHolding` is N+1.** `backend/internal/db/access_requests.go:160-185` loads every request; `backend/internal/handlers/access.go:233-252` runs one `RequestHolding` query per pending row. `/requests` and `/governance/summary` both pay this.
- **Cascades do per-user queries while holding the global access lock.** `backend/internal/services/cascade.go:415-458,524-577,593-647` loop every known user and call `userBaseHoldings`; each call performs direct-grant, bundle-role, and queued-revocation reads (`:221-253`). One rule/bundle change serializes every other access mutation behind O(N) round trips.
- **Cache rebuild recompiles every project per user.** `backend/internal/cache/compiler.go:163-169` invalidates all keys and loops every project; `backend/internal/handlers/bulk.go:172` calls it per applied bulk row.
- **Home polls a full directory reconciliation every 5 seconds.** `useMissedOnboarding` refetches every 5s (`ui/src/lib/queries/useOperations.ts:117-123`); the backend does a welcome-bundle read, bundle-holder read, full directory listing, and service-account read on every call (`backend/internal/services/onboarding_reconcile.go:64-109`).
- **Webhook and onboarding logs are unbounded and polled every 5 seconds.** `GetWebhookEvents` and `GetOnboardingTriggers` have no `LIMIT` (`backend/internal/db/webhooks.go:107-127`, `backend/internal/db/onboarding.go:88-94`); `useOperations.ts:90,107` polls them.
- **Target page re-renders a 1,955-line tree every 30 seconds.** `useTargetHealth` is subscribed at the top of `TargetOverview` (`ui/src/components/targets/TargetOverview.tsx:65`), polls at 30s (`ui/src/lib/queries/useTargets.ts:167`), and the file has no memoization. `useTargetInventory` is also subscribed twice (`:67`, `:1438`).
- **Bundle pickers fan out one request per bundle.** `useBundleRolesByBundle` (`ui/src/lib/queries/useBundles.ts:188-207`) and `useVersionsByBundle` (`ui/src/lib/queries/useBundleVersions.ts:123-128`) map every bundle id to its own request. “Manage bundles” on 30 bundles fires 30 requests.
- **Add-on reads are N+1 and unbounded.** `shareUsage` calls `pool.dataset.get_quota` per share (`addons/truenas/storage_status.go:139-184`); `readSharesACLs` lists and reads ACLs for every first-level folder with no cap (`addons/truenas/reach.go:213-251`); each apply reads subjects twice (`addons/truenas/apply.go:421,901`).
- **No server or outbound timeouts.** `backend/cmd/api/main.go:205-208` sets only `Addr`/`Handler`; JWKS uses `http.DefaultClient` (`backend/internal/auth/jwt.go:67-74`). Add `ReadHeaderTimeout`, `ReadTimeout`, `WriteTimeout`, `IdleTimeout`, and a bounded HTTP client.
- **The proxy buffers unbounded bodies.** `ui/src/app/api/proxy/[...path]/route.ts:131,180` reads the whole request and response; the backend’s 1 MB limit applies only after the proxy has already buffered.

## 5. Modularity / reuse

- **Nine mega-components mix data access, derivation, dialogs, and copy:** `TargetOverview.tsx` (1,955), `UnexplainedAccess.tsx` (1,501), `BundlePage.tsx` (1,233), `PersonAccess.tsx` (1,104), `Home.tsx` (978), `expiring-access/page.tsx` (872), `policies/page.tsx` (751), `users/page.tsx` (733), `MyStorage.tsx` (723). Extractable units are already visible: `SystemHealth`, `ReconcileControl`, `ResolveConflictDialog`, `DriftSection`, `TriageRow`, `WhatItGives`, `RemovalImpact`, `ProjectRoleTally`, `Home` queue blocks, `RuleEditor`, `PersonRow`, `TargetCard`.
- **Mutation-outcome state is reimplemented ~21 times.** `succeeded()` is copied in `UnexplainedAccess.tsx:1134`, `BundlePage.tsx:910`, `bundles/page.tsx:298`, `expiring-access/page.tsx:744`, and `RemovalDialog.tsx:168`. A shared `useMutationOutcome` + `<OutcomeSeat>` would remove the repeated “close on success vs keep the outcome visible” decisions.
- **The extend-grant flow exists three times:** `Home.tsx:550-625`, `PersonAccess.tsx:782-837`, `expiring-access/page.tsx:558-743`. `EXTEND_DAYS` is duplicated and Home uses a literal `90`.
- **`useLeavingRows` is quadratic and returns fresh arrays.** `props()` uses `kept.find(...)` per row (`LeavingRows.tsx:211-212`), and `rows`/`window` are new on every render (`:192,197`), so downstream memos never hit. `useRowSelection` also returns a fresh object every render (`useRowSelection.ts:354-372`).
- **`TargetOverview` subscribes `useTargetInventory` twice** (`:67`, `:1438`); `Makerspace` subscribes `useUsers`, `useGlobalRoleCatalog`, and `useBundles` twice each (`Makerspace.tsx:73-75,153,234-235`).
- **`BundlePage` downloads the whole bundle list to find one bundle** (`BundlePage.tsx:86-88`) although `useBundle` exists (`useBundles.ts:130-137`).
- **`useBundleRolesByBundle`/`useVersionsByBundle` fan out per bundle** instead of a batch endpoint.
- **No shared query-key registry.** Keys are hand-written in each hook; broad prefixes like `["users"]` refetch every user query (`useDrift.ts:124`, `useHolds.ts:126`, `useBulkGrants.ts:148-158`).
- **`/catalog` and `/bundles` are fetched twice under different keys** (`useNameResolver.tsx:211,220` vs `useCatalogUsers.ts:21` and `useBundles.ts:82`).
- **Wire types are duplicated and drifting.** `lib/types.ts:4-145` and the query hooks each define `ApplicationView`, `AccessRequest`, `ProjectSummary`, etc.; `ApplicationView` in `useApplications.ts` already has fields `lib/types.ts` lacks. `BulkEffect` duplicates `PlanEffect`; `{project_id, role_key}` is defined three times.
- **Formatting/derivation is duplicated:** expiry (`format.ts:95`), relative time (`format.ts:133`, `Time.tsx`), term endings (`term.ts`, `term-dates.ts`, `keep-ends.ts`), pluralization (`format.ts:269`, `Home.tsx:974`, `MemberAccess.tsx:423`), first names (`Home.tsx:959`, `MemberAccess.tsx:401`), role naming (`format.ts:19`, `Unresolved.tsx:30`, `Policies.tsx:215`), bytes (`format.ts:249`, `HomeLimit.tsx:27`), read freshness (`ReadFreshness.tsx:53-72` plus six manual constructions), and audit day grouping (`audit-vocabulary.ts:268`, `operations/page.tsx:378`, `RecentChanges.tsx:68`).
- **Demo identity is defined twice:** `ui/src/lib/session.ts:58-114` and `backend/internal/demo/catalog.go:10-14`. Avatar logic is duplicated too (`oidc.ts:236-242` vs `backend/internal/directory/zitadel.go:616-624`).
- **No code-splitting.** There are zero `next/dynamic`/`React.lazy` imports; `RehearsalDialog`, `TokenFormatEditor`, `ConnectionGuide`, and `PublishVersionDialog` are all in initial route JS. Route chunks are roughly 430–660 KB.
- **Server prefetch/hydration is configured but unused.** `query-client.ts:27-31` sets `dehydrate.shouldDehydrateQuery`, but there is no `HydrationBoundary` or `prefetchQuery` anywhere. Either wire it or delete the dead config.
- **`StatCard` uses a raw `<a>` for internal links** (`StatCard.tsx:51`), causing full document navigation and losing the React Query cache.
- **`Button`’s wrapper swallows layout classes.** `className` goes to the inner `<button>` (`Button.tsx:93`), but the outer `<span>` (`:125`) is the flex child; `order-*`, `w-full`, `ml-auto`, and `flex-1` on buttons do not affect the wrapper.

## 6. UX / accessibility

- **Home can say “Nothing needs you” when a read failed.** `loading`/`error` aggregate only summary, requests, and onboarding (`Home.tsx:194-195`); `useServiceAccounts` (`:141`) and `useIndicatorsRead` (`:98`) are omitted. A failed service-account read contributes zero and the block silently disappears.
- **Home claims a read time before any read.** It always renders `last checked <ClockTime at={summary.dataUpdatedAt} />` (`Home.tsx:213`); before the first success `dataUpdatedAt` is `0`, which `ClockTime` formats as a 1970 time (`Time.tsx:48-70`).
- **The rail shows fabricated zero badges before the first payload.** `useIndicators` uses `EMPTY` placeholders (`useIndicators.ts:45-55`), and `NavRow` renders `0` regardless of `isPlaceholderData` (`Sidebar.tsx:172-188`). `settled` only suppresses the flash.
- **Desktop filter popovers are unreachable by keyboard.** `FilterPanel` portals the desktop panel and never moves focus into it (`FilterPanel.tsx:120-157`; `Anchored.tsx:105-116`). Tab continues through the page; there is no dialog/menu role or focus return.
- **No skip link.** The shell renders the full sidebar before `<main>` (`layout.tsx:90-93`, `AppShell.tsx:80`); keyboard users must tab through every nav row on every page.

## 7. Security / contracts / deployment

- **Forwarded host/proto are trusted without an allowlist.** `resolveRequestOrigin` prefers `x-forwarded-host` and `isSecureRequest` trusts `x-forwarded-proto` (`ui/src/lib/request-url.ts:36-71`). With the UI published directly (`docker-compose.yml:165`), a spoofed header can change redirect targets or mark the session cookie non-`Secure`.
- **Mutations have no Origin/CSRF check.** The proxy accepts state-changing methods without checking `Origin`/`Referer` (`route.ts:82-188`); `SameSite=Lax` is the only defense. Login/logout are also cross-site POSTable (`auth/login/route.ts:12-39`, `auth/logout/route.ts:12-16`).
- **Middleware’s static-asset heuristic bypasses auth for any path containing a dot.** `pathname.includes(".")` (`ui/src/middleware.ts:104-110`) skips session and member-nav checks for `/users/foo.bar` and similar.
- **Authenticated proxy responses have no cache directive.** `NextResponse.json(data, { status })` (`route.ts:184`) sets no `Cache-Control: private, no-store` or `Vary: Cookie`, and discards backend headers such as `Retry-After`.
- **Logout does not revoke the token.** It only deletes the local cookie (`auth/logout/route.ts:12-16`); there is no end-session/revocation call.
- **Demo mode is a silent fallback selected by a missing env var.** `ZITADEL_DOMAIN == ""` switches auth to the shared API key and makes `isOperator` always true (`router.go:413-420`), disables webhook/action signature verification (`zitadel_action_auth.go:56-61`), and enables demo sessions. Compose defaults the API key to `dev_auth_token_secret` (`docker-compose.yml:44,169`). A production deploy with a missing/typo’d `ZITADEL_DOMAIN` becomes an operator-level demo.
- **`ZITADEL_AUDIENCE` is not validated at startup.** A live backend with it empty starts and returns 500 on every authenticated request (`router.go:424-429`).
- **Configuration is misleading:** `PORT` is passed but the server hardcodes `:8080` (`main.go:206`); `NEXT_PUBLIC_API_URL` is passed but unused (`docker-compose.yml:167`); `CORS_ORIGIN` defaults to localhost (`router.go:557-559`).
- **The add-on self-account guard fails open.** `refuseSelfAccount` returns nil when `auth.me` is unknown and matches only on name, not UID (`addons/truenas/operations.go:309-315`). A transient `auth.me` failure lets an operator adopt or purge the add-on’s own target account; purging deletes Syndra’s credential.
- **The add-on binding store has no username uniqueness or compare-and-swap.** `adoptAccount` checks `BoundUsernames` and later calls `PutBinding` in separate transactions (`operations.go:1048-1091`, `store.go:288-299,334-346`). Two subjects can bind the same username concurrently.
- **Account creation is not resumable after a crash.** `group.create` runs before `user.create` (`apply.go:826-862`); `undoGroup` only runs on a returned error. A crash or lost response leaves an orphan group, and a replay fails on the existing group.
- **Purge reports success when the binding cannot be deleted.** `operations.go:455-470` logs the `DeleteBinding` failure and still returns `succeeded`; the binding survives and a later apply can recreate the purged account.
- **Capability availability withdraws local operations when the target version is unknown.** `availability` checks `MajorSupported()` before `methodsFor` (`addons/truenas/server.go:119-128`), so `account.release` — deliberately declared with no target methods — becomes unavailable during an outage, exactly when it is needed (`capabilities.go:142-147`).
- **`activity.get` silently truncates at 200 rows.** `addons/truenas/operations.go:565-586` sets `limit: 200` with no offset or `truncated` flag; older events disappear with no warning.
- **The manifest and wire disagree on `home`/`home_quota` types.** The manifest declares `home: bool` and `home_quota: int` (`capabilities.go:108-115`), while `EntitlementSet.Desired` encodes every non-lifecycle field as `[]string` (`backend/internal/services/entitlement.go:471-498`) and the add-on decodes lists (`apply.go:255-282`).
- **Direct read legs bypass the effective-operation gate.** `ReadValues`, `ReadSettings`, `ReadHomes`, `ReadReach`, `MyStorage`, `Activity`, and `SystemHealth` call `doAuthenticated` directly (`backend/internal/addons/read.go:604-631,648-681,701-712,730-753,809-853,906-960,1031-1078`), so manifest availability and policy scope are not enforced for reads.
- **The add-on’s mutation log does not truncate a partial trailing line.** `OpenMutationLog` opens with `O_APPEND` (`mutationlog.go:129`), `recoverHead` skips a malformed trailing line (`:163-178`), and `Append` writes after the partial bytes (`:232-258`). The next append concatenates two records into one unparseable line.
- **The transport record is consumed before the request is known to be sent.** `backend/internal/addons/transport.go:241-246` calls `Record.consume` before `doAuthenticated`; a canceled context or request-construction failure leaves the record spent and the call reported “never sent.”

## 9. What is already strong

- Strict JSON decoding, body caps, HMAC webhook verification, constant-time API-key comparison, and self-or-operator checks on the main per-user routes.
- The access-mutation advisory lock, `FOR UPDATE SKIP LOCKED` drain, guarded terminal transitions, and 409-as-idempotent handling.
- The observation model’s “only a complete read may conclude absence” rule is well designed — the add-on reconcile path is the place that breaks it.
- Plan claims are atomic and carry target, surface, actor, fingerprint, and expiry.
- The cancellation preview and write share one predicate.
- `holdersLine` and the one-snapshot holder-count design are the right pattern; the role detail page is the one screen that bypasses it.

## 10. Suggested order

1. **Repair the cache lifecycle** — rebuild after drain, or compile on miss; add a test that a token still carries claims after an applied grant.
2. **Fix the proxy contract** — add `PATCH`, forward `DELETE` bodies, handle 204/empty bodies, and add a router/proxy method parity test.
3. **Make webhook and onboarding failures retryable** — inspect existing row status on conflict; retry `failed`; add a redelivery test.
4. **Fix date semantics** — send an explicit end date for grants; validate holds against the future.
5. **Make grant-read failures explicit** — never render “No end date” or “Given to you” from an errored read.
6. **Close the authorization gap** — operator-gate role creation, simulation, and logs; stop publishing the backend port; add a route-gate test.
7. **Fix the add-on apply replay and shutdown drain** — persist HTTP status with the idempotency entry, reject blocked outcomes, and make shutdown exceed the call timeout.
8. **Consolidate the duplicated facts** — one count source for governance, one held set for members, one published bundle count, one target health reading, one name cache, one expiry formatter.
9. **Delete the dead code and merge the duplicated helpers** — start with `lib/api.ts`, dead `lib/types.ts` types, dead `format.ts` exports, and the five `succeeded` copies.
10. **Do the a11y pass** — filter-panel focus, tabs/radio semantics, skip link, modal labels/inert, contrast tokens.
11. **Then the structural refactors** — split the mega-components, central query keys/invalidation, batch bundle endpoints, and add server prefetch or remove the dead dehydrate config.
