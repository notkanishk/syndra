Problem. No module owns "which outbox writes does this operation cause". Four of five bulk operations and the bulk decision derive them once to preview and again to apply, so the preview can promise something the apply doesn't do (a bundle removal misses roles held through a mapping rule).

Solution. A planner module takes an operation and returns its writes. Rehearsal runs it as a dry run and apply commits the same writes, and the guards (role offered, already held) live inside it once.
