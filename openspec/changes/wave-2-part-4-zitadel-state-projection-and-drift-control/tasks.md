- [x] **Task 10f** — Detach the compiled-cache rebuild from the request lifecycle. *(B4/D3)*
  - Follow-up to 10e's residual: reordering stopped the *drain* from starving the rebuild, but the rebuild still inherited `r.Context()`, so a client disconnect *before* the rebuild started could still skip it. New `rebuildUserCacheDetached` runs it on `context.WithTimeout(context.WithoutCancel(r.Context()), 10s)` — after commit the grant is durable, so the rebuild that makes access effective must complete regardless of client lifecycle. Applied to both grant paths (`handleUpsertUserDirectGrant`, `handleResolveAccessRequest`). It stays synchronous (handler still finishes the rebuild before responding); it just no longer inherits request cancellation. (`handlers/access.go`)
  - Tests: 2 new `...RebuildDetachedFromClientCancel` tests — issue the request with an already-canceled context and assert the cache rebuild still runs AND receives a non-canceled context. Full backend suite green (387 pass), `go vet`/`gofmt` clean.
