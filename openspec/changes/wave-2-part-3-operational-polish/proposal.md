# Wave 2 · Part 3 — Operational Polish

**Status:** Proposed
**Source:** [May 2026 audit resolution design](../../../docs/superpowers/specs/2026-05-08-may-2026-audit-resolution-design.md) §3 Theme 5 — audit refs **B8, S1, S2, S3, S4, C7, C8, C9, C10, D4, D7, D9**
**Phase:** 5.5
**Wave:** 2 (Part 3 of 4 — installation, dev-experience, sync polish; Parts 1, 2, 4 cover frontend palette, backend coherence, and drift control)

## Why

Eleven audit findings span three subsystems — backend (`B8`), sync service (`S4`, `C7`, `C8`, `C10`), zitadel-action scripts (`S1`, `S2`, `S3`), deployment surface (`D7`, `D9`, `C9`), and one cross-cutting spec drift (`D4`). None are user-visible defects; together they are the difference between a deployment that "ships" and a deployment an operator can pick up six months from now without re-reading commit logs.

The findings cluster cleanly by *kind of mess*: vestigial code that no longer pays its way (`C10`'s no-op zero-buffer, `D4`'s unused version column, `B8`'s 100-page lookup cap sized for a SaaS that doesn't exist), undocumented runtime surface (`D7`'s missing sync-env block, missing `MKAUTH_EXTERNAL_URL` / `ZITADEL_M2M_TOKEN` in the backend block, `S4`'s hardcoded retry constants masquerading as env-readable), copy-paste accumulation (`S1`'s 22-line env-loader duplicated across `register.sh` and `rotate.sh`), and stale framing (`D9`'s `N > 1 replicas` comment block, `C9`'s smoke-test probing an authenticated endpoint when `/healthz` exists). Each is trivial; resolving them in one wave keeps the cleanup focused and the diff reviewable as a single operational-polish unit.

This wave is parallelisable with Wave 2 · Part 2 (backend coherence) — no overlapping files. It is a hard prerequisite for nothing, but landing it now keeps the deployment surface coherent before Wave 2 · Part 4 (drift control) introduces new env vars and new scripts.

## What changes

  - `backend/internal/db/rules.go:UpdateMappingRule` (the column's only writer) is deleted; `version` is dropped from `GetActiveMappingRules`' `SELECT` and `Scan`.
  - `backend/internal/handlers/rules.go:handleUpdateMappingRule` (lines 128-144) is deleted — the audit log it emits (`mapping_rule.version_bumped`) is removed with it.
  - `backend/internal/handlers/router.go:60` — the `PUT /api/v1/rules/mapping/{id}` route is unregistered.
  - `backend/internal/handlers/deps.go:44` — the `dbUpdateMappingRule = db.UpdateMappingRule` injectable is deleted.
  - `backend/internal/handlers/rules_test.go` — the three `TestHandleUpdateMappingRule_*` tests are deleted; `resetRulesDeps` drops its `origUpdate` save/restore.
  - `backend/internal/models/models.go:37` — `Version int` field removed.
  - `backend/internal/services/views.go:700` — `"version": fmt.Sprintf("%d", rule.Version)` Topology meta line removed.
  - `ui/src/lib/queries/useMappingRules.ts:13` — `version: number` removed from `MappingRuleRow` (the live type consumed by `/policies`, `/projects`, and `GrantsClient`).
  - `ui/src/lib/queries/useMappingRules.ts:77` — `useBumpMappingRule` mutation and its JSDoc deleted.
  - `ui/src/lib/types.ts:59` — `version: number` removed from the stale `MappingRule` type (zero importers today, but kept consistent with the live type).
  - `ui/src/app/policies/page.tsx` — drop `useBumpMappingRule` import (line 16), the `bumpRule = useBumpMappingRule()` binding (line 38), the `handleBump` async function (line 45-49), the `<Badge>v{rule.version || 1}</Badge>` (line 96), and the `<Button>...Bump version →</Button>` block (around lines 135-145 — note the surrounding `<div className="flex items-center justify-end mt-3 pt-3 border-t border-outline-variant/50">` becomes empty and is removed too).

  Operator rule edits flow through `DELETE` + `CREATE`, with both halves persisted in `audit_logs` (which already happens). The `feature-coverage.md` "Versioned policies" row flips from *Partial* to *Removed — rely on `audit_logs`*.
- **`.env.example` sync-service / LLDAP block + two missing backend vars (D7).** A new `--- Sync Service / LLDAP ---` section is appended, documenting every env var in `sync/internal/config/config.go` (`BACKEND_URL`, `MKAUTH_API_KEY`, `LLDAP_URL`, `LLDAP_BIND_DN`, `LLDAP_BIND_PASSWORD`, `LLDAP_BASE_DN`, `LLDAP_INSECURE_SKIP_VERIFY`, `SYNC_POLL_INTERVAL`, `SYNC_WORKER_COUNT`, `SYNC_INTENT_LIMIT`, `SYNC_RETRY_ATTEMPTS`, `SYNC_RETRY_BACKOFF`). The backend block gains `MKAUTH_EXTERNAL_URL` and `ZITADEL_M2M_TOKEN`, both required at runtime but absent from the template today. Each entry carries a one-line description and the canonical default (or `# required, no default` when there isn't one).
- **`.env.example` `EXPIRY_SCHEDULER_*` framing (D9).** The "Set to false on extra replicas when running N > 1 backend instances" comment block is rewritten to reflect the single-LXC reality. The toggle stays (it's still useful for ops experimentation); the multi-replica rationale is dropped.
- **`scripts/lib/load-env.sh` extracted; sourced from `register.sh` and `rotate.sh` (S1).** The 22-line env-loader block at `zitadel/actions/register.sh:74-95` and `zitadel/actions/rotate.sh:55-76` is identical character-for-character. The extracted helper takes a single optional argument (the env-file path, defaulting to `<repo>/.env`) and exports any `KEY=VALUE` line not already in the environment, preserving the existing `[[ -z "${!_k+x}" ]]` precedence rule. The two scripts each replace their 22-line block with one `source` call.
- **`scripts/lib/zitadel-api.sh` NOT extracted (S2 deviation).** The audit listed both helpers in one item. Investigation found `zitadel_api()` lives in `register.sh:139-162` and has **zero duplication** — `rotate.sh` calls into `register.sh`'s function via direct script invocation; the helper is single-consumer. Extracting it now would be YAGNI and worse: it would couple a future second consumer to an interface designed for the first. Deviation documented in `design.md` Decision 4.
- **Fold `zitadel/actions/{PERMISSIONS,SIGNING_KEY}.md` into `README.md` (S3).** Both docs are read sequentially during action deployment and are tightly coupled to the README's step-by-step flow. They become `## Service-Account Permissions` and `## Signing Key Handling` sections inside `README.md`. The original files are deleted. `EVENTS.md` stays separate — its audience is the event-listener path, not the action-registration path.
- **`SYNC_RETRY_ATTEMPTS` + `SYNC_RETRY_BACKOFF` read from env (S4).** `sync/internal/config/config.go:42-43` currently hardcodes `RetryAttempts = 3` and `RetryBackoff = 1 * time.Second`. The values are read via the existing `getEnvInt` / `getEnvDuration` pattern alongside the rest of the sync config surface. `worker.go:retryTransient` (the consumer) is unchanged.
- **LDAP `groupOfNames` member uses bind DN, not empty string (C7).** `sync/internal/ldap/client.go:170` initialises a new group with `addReq.Attribute("member", []string{""})`. The empty placeholder works against LLDAP's permissive schema check but would be rejected by strict OpenLDAP. The bind DN is already in scope via `p.cfg.BindDN`; the placeholder becomes `[]string{p.cfg.BindDN}`. This is a "no functional change today, survives future LDAP backend swap" fix.
- **`withConn` plumbs `context.Context` (C8).** `sync/internal/ldap/client.go:73`'s `func (p *Pool) withConn(fn func(*ldapv3.Conn) error) error` becomes `func (p *Pool) withConn(ctx context.Context, fn func(*ldapv3.Conn) error) error`. The body checks `ctx.Err()` at three places: before attempting `p.mu.Lock()`, immediately after the lock is acquired, and before any reconnect retry. All call sites (`EnsureUser`, `EnsureGroup`, `AddUserToGroup`, `RemoveUserFromGroup`, `SetUserPassword`, `Search`, etc.) thread the `ctx` they already accept. **What this delivers, precisely:** an LDAP op queued behind another goroutine's `withConn` will, upon eventually acquiring `p.mu`, see its cancelled ctx and return `context.Canceled` without issuing an LDAP request. An LDAP op that hasn't yet attempted to acquire the mutex fails immediately. **What this does NOT deliver:** the active LDAP call holding the mutex is not interrupted — it runs to completion (or the underlying conn timeout) and only then is the mutex released. Mid-LDAP-call cancellation would require closing the connection from another goroutine and fighting the reconnect path; that complexity is not justified for the worker-shutdown use case (see `design.md` Decision 3).
- **`scripts/smoke-test-lxc.sh` probes `/healthz` (C9).** Line 11's `curl -fsS -H "Authorization: Bearer ${API_KEY}" "http://${HOST}:8080/api/v1/bundles"` becomes `curl -fsS "http://${HOST}:8080/healthz"`. The Authorization header is dropped from the API check. The smoke test now works on real OIDC-mode LXC deployments where the operator does not have a bearer token to hand the script.
- **Drop the shadow-password zero-buffer defer (C10).** `sync/internal/worker/worker.go:191-195` defers a loop that zeros `hashBytes`. The bytes were created via `[]byte(hash)` from an immutable Go string; the original `hash` string keeps the secret in memory regardless of what the slice contains, and the slice is GC'd seconds after the function returns anyway. The defer is theatre. It is deleted; a 2-line comment at the deletion site documents the immutability constraint so a future contributor doesn't re-add it.
- **`grantLookupMaxPages` from 100 to 10 (B8).** `backend/internal/handlers/zitadel_grant_lookup.go:15` bounds the fallback pagination loop. At `DefaultSearchLimit = 100` per page, 10 pages cover 1000 grants for a single user — already two orders of magnitude beyond what the makerspace audience generates. The 100-page cap was defensive carryover from a different sizing assumption. The comment above the constant is updated to reflect the new sizing rationale.
- **Spec deltas.** One capability receives added scenarios (no existing requirements modified):
  - `ldap-sync/spec.md` — Empty-DN placeholder replaced with bind DN; worker-shutdown context cancellation propagates to in-flight LDAP ops; retry attempts/backoff configurable via env.
- **`feature-coverage.md` updates.** Two rows shift status:
  - *Versioned policies* (line 45) → *Removed; rely on `audit_logs`*.
  - *LDAP Sync — retry* row gains "env-configurable" qualifier.
- **Regression coverage.** New tests cover: (a) `EnsureGroup` adds a group with `member = [bindDN]` against a fake LDAP server; (b) `withConn` returns `ctx.Err()` before acquiring the connection mutex when context is already cancelled; (c) `loadConfig` reads `SYNC_RETRY_ATTEMPTS=5` and `SYNC_RETRY_BACKOFF=250ms` from env and falls back to `3` / `1s` when absent; (d) `listUserGrantsViaZitadel` exits via the new 10-page bound; (e) the down migration restores the `mapping_rules.version` column with default `1` if rolled back.
