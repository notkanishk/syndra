## Review fixes (post-implementation)

- **P2 / proxy bodyless PUT (`ui/src/app/api/proxy/[...path]/route.ts`)** — proxy now reads the request body via `request.text()` and only parses/forwards when non-empty. `useSetWelcomeBundle` was sending a clean bodyless PUT (idiomatic REST for an idempotent toggle); the prior unconditional `request.json()` would throw before the request reached the backend. Empty bodies now forward without `Content-Type` and without an `init.body`. Member-role and demo-admin payload injection branches handle the `body === null` case via `... ?? {}`.
- **P2 / welcome route operator-gated (`backend/internal/handlers/router.go`)** — `PUT /api/v1/bundles/{id}/welcome` now wraps `withOperatorAuth(handleSetWelcomeBundle)` instead of `withUserAuth(...)`. The welcome flag controls global onboarding policy, so the gate matches the blast radius. The `automation-policies` Wave 1 spec delta gains a new "Operator-only authorization" requirement. In dev mode `withOperatorAuth` falls through to `withAPIKeyAuth` (matching prior dev semantics).
- **Open question / migration auto-promote — resolved** — chose **observability-only**: migration still leaves all rows at `FALSE` (preserves explicit-only contract), but `cmd/api/main.go` now calls `warnIfWelcomeBundleMissing(ctx)` after `seed.EnsureDemoData`, emitting `[STARTUP] WARNING: no welcome bundle configured — onboarding triggers will fail until an operator sets one (PUT /api/v1/bundles/{id}/welcome).` Spec delta updated with a new "Startup warning when unconfigured" requirement. Demo dev mode trips this every boot until an operator (or a future seed change) sets a welcome bundle — informational, fine for dev.
