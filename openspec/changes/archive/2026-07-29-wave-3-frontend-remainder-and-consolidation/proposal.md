# Wave 3 — Frontend Remainder & Consolidation

**Status:** Proposed
**Source:** [May 2026 audit resolution design](../../../docs/superpowers/specs/2026-05-08-may-2026-audit-resolution-design.md) §6.1 Wave 3 (Theme 4 remainder) + §7 consolidation — audit refs **U1, U4, U5, U6, U7, D2, D6**, plus three folded-in Wave 2 residuals **R1, R2, R3**

## Why

Wave 2 landed the four heavy themes (palette finalization, backend coherence, operational polish, drift control). What remains is the **non-palette half of Theme 4** — UI refactors and test gaps that were explicitly deferred to Wave 3 in both Wave 2 · Part 1 and Part 2 proposals — and the **consolidation pass** that trues up the cross-cutting docs to post-cleanup reality.

These findings cluster by *kind*: complexity that outlived its need (`U1`'s 409-line rAF-batched name resolver where a 200-user org can hold the whole catalog in a `Map`; `U5`'s 955-line `zitadel/page.tsx` that never got split), dead weight (`U4`'s four exportless-consumer fetchers; `R1`'s superseded `HasPendingDrift`; `R3`'s copy-pasted `zitadel_api()` bash), missing safety net (`U7` — the admin/member boundary in `middleware.ts` and the proxy route has zero test coverage), a small correctness nit (`U6` avatar fallback), a spec-drift closure (`D2` ⌘K roadmap stub), and one deliberate field removal (`D6` `location`).

`D6` is the one decision that reverses shipped behavior: Wave 1 (C2/D5) wired `location` end-to-end into the OIDC session so it renders on the member dashboard. The operator has decided to **drop `location` entirely** — its value never justified the vertical it occupies (backend profile → directory metadata → OIDC callback → session cookie → two render sites). Wave 3 removes the whole vertical, keeping `title` and `team`, which remain meaningful.

`R2` folds in the one design element Wave 2 · Part 4 left unbuilt: the inline per-grant `[⏱ Awaiting Zitadel]` tag from design §5.2. It is optional polish (aggregate pending surfaces already convey the information), but it completes the drift/pending UI contract.

This wave is the natural home for the consolidation step because it is the last audit-resolution change; archiving it leaves `INDEX.md`, `ROADMAP.md`, `feature-coverage.md`, and `design.md` describing exactly what shipped.

## What changes

- **U1 — Full-catalog name resolver.** `ui/src/lib/queries/useNameResolver.tsx` (409 lines) currently batches UID→name lookups per animation frame and fires `POST /api/v1/lookup` per batch. It is replaced with a single catalog fetch on `<NameResolverProvider>` mount, feeding four in-memory `Map`s; every `resolveUser`/`resolveProject`/`resolveRole`/`resolveBundle` becomes a synchronous `Map` read. **The catalog is two independent fetches, not one** — `GET /api/v1/catalog` covers users + projects + nested roles, but not bundles, so `GET /api/v1/bundles` is fetched as a **separate, non-retrying query**. This matters because the provider is mounted globally and the proxy allows member `GET /catalog` but forbids member `GET /bundles` (403): a shared/`Promise.all` fetch would let the bundles 403 sink user/project/role resolution on every member page. Independent queries isolate it — the bundles query soft-fails to fallback for members (who don't surface bundle names), while catalog resolution works. Net: members *gain* user/project/role names (catalog is member-allowed) where today's member-forbidden `POST /lookup` gave them fallback. The proxy boundary is left untouched. The public interface is preserved verbatim: `NameResolverProvider`, `useNameResolver()` returning `{ resolveUser, resolveProject, resolveRole, resolveBundle, prefetch }`, each resolver returning the tri-state `ResolveResult<T> = { value, resolved }`. Semantics preserved: `resolved:false` while the initial catalog load is in flight (consumers render skeletons); `resolved:true, value:undefined` once loaded but the id is absent (consumers render fallback). `prefetch()` becomes a no-op (the catalog is already complete). The React Query catalog key is invalidated on user create/delete so new users resolve without a reload. Consumers unchanged: `UserName`/`RoleName`/`BundleName`/`ProjectName`, `GrantsClient`, `audit/page.tsx`.
- **U4 — Delete dead `lib/api.ts` fetchers.** Remove `fetchBundles` (line 70), `fetchMappingRules` (74), `fetchProjects` (86), `fetchAudit` (90) — all with zero importers in `ui/src`. Drop the now-unused type imports (`AuditLog`, `Bundle`, `MappingRule`, `ProjectSummary`) from line 2. `fetchApplications`, `fetchWithAuth`, `fetchSystemMode`, `fetchCatalog`, and the internal `fetchServerJson`/`resolveAuthToken` helpers stay. **`lib/types.ts` is NOT consolidated into per-resource hooks** (operator decision: the 14 shared interfaces earn their central home; scattering them is churn without payoff).
- **U5 — Split `app/zitadel/page.tsx` + unified client + admin guard.** The 955-line page is decomposed into `ui/src/components/zitadel/{Health,Rotation,Projects,Users,AllGrants}.tsx` (one file per existing section) plus a `ZitadelDiagnostics.tsx` client island. The three page-local fetch helpers (`apiGet`, `apiGetDiagnostic`, `apiSend`) are deleted and replaced with `request<T>` from `ui/src/lib/api-client.ts`. `apiGetDiagnostic`'s distinguishing behavior (return the parsed body on non-2xx instead of throwing, used only by the health probe) is captured by a new `{ preserveErrorBody?: boolean }` flag on `request`'s options. The async grant-response handling (`grantFlash` reading `.status`) is already correct from Wave 2 · Part 4 and is carried over unchanged. **This also closes a gating gap found in P2 review:** `app/zitadel/page.tsx` is today a monolithic `"use client"` component gated by *neither* middleware nor a page guard (a member is stopped only by the proxy 403'ing its data calls — the admin surface still hydrates). The rewrite makes `page.tsx` an async server component with the canonical guard (`getSession()` → `redirect`, as `/grants` does), rendering the client island. Defense-in-depth, folded into the file U5 already rewrites.
- **U6 — Avatar fallback.** `ui/src/lib/session.ts:224` computes the OIDC avatar as `nameToAvatar(payload.name)`. When `payload.name` is empty (name not yet propagated), the initials come out blank. The fallback chain becomes: `name` → `email` local-part → `userId`, so an avatar is always non-empty.
- **U7 — Security-boundary tests.** Add Vitest coverage (currently zero) for **both** admin/member enforcement mechanisms (the boundary is a two-mechanism split — P2 review; see design.md Decision 8):
  - `ui/src/middleware.ts` — redirect for `role:"user"` on each `ADMIN_ONLY_PATHS` entry, stale-demo-cookie clearing when `ZITADEL_DOMAIN` is set, expired-OIDC → `/login`, `valid`-on-`/login` → `/`.
  - **Page-level server guards** (`ui/src/app/__tests__/admin-page-guards.test.ts`) — `/operations`, `/operations/cascades`, `/governance/pending`, `/governance/drift`, `/grants` (and `/zitadel`, guarded by U5): non-admin → `redirect("/")`, no session → `redirect("/login")`, admin → renders. These routes are gated at the page, not middleware, and had zero coverage.
  - `ui/src/app/api/proxy/[...path]/route.ts` — member self-scoping (`users/{ownId}/grants` allowed, `users/{otherId}/...` 403), allowlist enforcement (member GET limited to `catalog|applications|requests`+self — incl. `GET /bundles` → 403, the boundary the U1 resolver tolerates; member POST limited to `requests`; all other writes 403), and the `requester_id`-forced-injection / list-filtering behavior.
- **D2 — ⌘K roadmap stub.** The spec strike is already done (`design.md §5`, `feature-coverage.md`). Add the missing `- [ ] **Optional: ⌘K command palette**` bullet to `ROADMAP.md` Phase 6.
- **D6 — Drop `location` end-to-end.** Remove the field from the full vertical, keeping `title`/`team`:
  - Backend: `models.UserProfile.Location` (`models.go:69`), the directory metadata read + empty-init (`directory/zitadel.go:197-198,491`), demo catalog (`demo/catalog.go:10-14`), and the profile handlers' passthrough (`handlers/profile.go`). Update `directory_test.go:492-493`, `profile_test.go:46,63`.
  - Frontend: `types.ts:44`, `session.ts` (OidcSessionCookie field :14, SessionUser field :40, demo data :68/80/92/104/116, legacy-decode default :165, OIDC assignment :223), `oidc.ts` (`ProfileMetadata.location` :227, default :242, `fetchProfileMetadata` read :253), the callback write (`auth/callback/route.ts:139`), and the two render sites (`app/page.tsx:56`, `login/page.tsx:127`). Update `session.test.ts`.
  - Specs: MODIFIED delta in this change's `user-management` capability; `feature-coverage.md:24` row; the `live-directory-identity-completeness` change (the field's owning capability). Shipped-change specs (`wave-1`) are left as historical record — not rewritten.
- **R1 — Delete dead `HasPendingDrift`.** `backend/internal/db/drift.go:126` `HasPendingDrift` has zero callers; `db.PendingOutboxAddExists` (`propagations.go:113`) is its functional successor and is the one actually wired in `services/drift/deps.go`. Delete the dead function and its doc comment.
- **R2 — Inline §5.2 pending tag.** In the per-user grants surface (the post-U5 `components/zitadel/Users.tsx`), join `usePendingPropagations()` client-side into a `Set` of pending `user|project|role` keys (matching `PendingRow.role_keys[]` membership for `op_type:"add"`), and render the `[⏱ Awaiting Zitadel]` tag with a "Resume" link to the dashboard next to affected grants.
